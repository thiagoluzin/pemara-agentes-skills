# Produção Phaser

Parta do gênero, dispositivo, controles, loop e escopo já escolhidos. Num jogo existente, confira o ponto de entrada, package.json, lockfile e recursos disponíveis. Só pergunte o que impedir uma decisão útil; planejar não suspende um pedido de implementação.

Defina o primeiro minuto: ação central, resposta audiovisual, condição de sucesso/falha e reinício. Construa um encontro completo antes de multiplicar conteúdo. Um pitch legível não demonstra diversão: registre observações de playtest e decisões ainda subjetivas.

Distribua responsabilidades pelo problema: gameplay para cenas/saves; combat para lanes/ataques; platformer para saltos; input para dispositivos; animation para clipes/porte; art para apresentação; audio para mix; level-design para encontros/curva; qa para regressão; performance para medição; release para distribuição. Os nomes completos têm prefixo phaser-. Carregue somente a skill instalada pertinente. Se faltar, execute o papel com os recursos disponíveis, sem inventar uma chamada de ferramenta.

Papéis podem ser exercidos pelo agente atual. Delegação só quando permitida e útil, com dono dos arquivos, entradas, saída verificável e dependências claras. Não imponha modelo, esforço, número de agentes ou serviços externos.

Expanda em marcos jogáveis: núcleo → conteúdo → transições contínuas → apresentação → verificação no alvo. Mantenha controles, identidade visual e regras aprovadas. Conteúdo gerado precisa de referência, origem e revisão; o orçamento e as tentativas seguem a autorização existente.

Para cada marco registre arquivos responsáveis, critério observável, comando de verificação, artefato e pendência. Descubra os gates reais do projeto; não presuma que scripts deste kit sejam gates do jogo. Não acrescente backend, multiplayer, contas, editor ou pipeline de IA sem necessidade do escopo.

Ao entregar, diferencie implementado, testado, medido, avaliado visualmente e pendente. Conclua o trabalho autorizado; build iniciado não é build entregue.
